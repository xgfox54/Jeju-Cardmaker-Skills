# 어려운 AI 개념의 업무 예시와 설명 그림

## 적용 기준

서귀포시 직원이 처음 접하는 AI 개념을 설명할 때 적용함. 친숙한 업무 상황 하나와 그 상황을 보여주는 그림을 중심으로 구성함. 모든 주제를 주민설명회로 바꾸거나 장수를 8장으로 고정하지 않음. 단순 공지나 숫자 한 개에 불필요한 그림을 추가하지 않음.

## 문안 작성

1. 직원이 실제로 할 일을 먼저 제시함. 행사 안내문 찾기, 회의자료 정리, 민원 안내 초안 작성처럼 대상을 구체적으로 씀.
2. 한 편에서 사용할 업무 예시를 정하고 등장하는 부서·업무·문서 이름을 유지함. 확인되지 않은 부서명·업무분장은 가상 예시로 표시함.
3. 예시를 보여준 뒤 필요한 용어만 설명함. 뜻을 설명하지 않은 ‘정의·도출·모델링’ 같은 말을 쉬운 말처럼 반복하지 않음.
4. 한 장에는 전달할 내용 하나와 짧은 설명을 둠. 예시 설명과 용어 설명이 중복되면 문장을 줄이고 그림으로 보여줌.
5. 마지막에는 자기 업무에 적용하는 작은 연습을 제시함. 간단한 그림을 그리면 시스템이 완성되거나 AI가 자동으로 정확해진다고 설명하지 않음.

## 그림 선택

| 설명할 내용 | 그림 | 확인할 점 |
|---|---|---|
| 종류와 구체적인 사례 | 종류별 상자와 사례 이름 | 부서라는 종류와 A팀이라는 대상을 구분함 |
| 대상 사이의 관계 | 상자와 방향 있는 연결선 | 선 위에 담당·사용 등 관계 이름을 표시함. 시간 순서와 혼동하지 않음 |
| 상위·하위 종류 | 큰 상자 안의 작은 상자 | 포함 방향과 실제 포함 여부를 확인함 |
| 입력·처리·결과 | 단계별 도형 | 단계 이름과 입력·결과물을 구체적으로 씀 |
| 차이와 변경 | 같은 기준의 좌우 또는 위아래 비교 | 바뀐 항목이 보이도록 같은 대상과 기준을 사용함 |

그림은 본문 내용을 설명해야 함. 본문에 없는 사실이나 관계를 그림에서 추가하지 않음. 색상만으로 의미를 구분하지 않고 각 상자에 이름을 표시함. 기술 관계를 나타내는 화살표는 문장 장식용 기호와 구분하여 사용함.

## 여백과 캐릭터

상단의 제목·짧은 본문, 중하단의 설명 그림, 요약과 캐릭터 순으로 읽히도록 배치함. 아래에 큰 빈 공간이 남으면 그림을 그 공간에 배치하고 읽기 좋은 크기로 키움. 공간을 채우기 위한 반복 문장이나 장식은 추가하지 않음.

캐릭터는 그림 옆, 요약 옆 등 남은 공간에서 설명을 돕도록 배치함. 특정 하단 모서리에 고정하지 않음. 표지와 마지막 장에는 제주 펫 3종을, 중간 장에는 주제에 맞는 동작 포즈를 사용함. 연결선과 이름, 요약, 각주를 가리지 않도록 확인함.

기존 Pretendard와 제주 3색을 유지함. 테두리 바깥 좌측 상단의 원은 오렌지·블루·그린 순서이며, 사각형 라벨은 가로·세로 가운데 정렬함. 줄바꿈을 조정해도 단어와 조건을 임의로 삭제하지 않음.

## 제작 경로와 예제

기본 `build`와 `plan.json` 스키마에는 설명 그림 필드가 없음. 지원하지 않는 필드를 추가하거나, 문장만 렌더링하고 그림까지 제작했다고 보고하지 않음. 아래 예제를 작업 폴더에 복사하여 전용 렌더러를 사용하거나 해당 주제에 맞는 그림 렌더러를 작성함. 설치 폴더에 결과물을 저장하지 않음.

- 예제 폴더: `assets/ontology-visual-example/`
- `plan.json`: 8장 문안
- `diagrams.json`: 상자·관계·포함·변경 그림의 글자
- `visual_renderer.py`: 같은 좌표로 PNG와 편집형 PPTX를 만드는 그림 배치
- `build.py`: 기존 제작·검사 기능을 사용하는 예제 실행기
- `SOURCES.md`, `research-notes.md`: 근거와 가상 예시의 구분

예제를 작업 폴더로 복사한 뒤 실행함. `<SKILL>`은 현재 SKILL.md가 있는 폴더의 절대 경로임.

```text
python <PROJECT>/build.py --skill-root <SKILL> --out <NEW_OUTPUT>
python <SKILL>/scripts/Jeju_Cardmaker.py verify-build --run <NEW_OUTPUT>
```

이 실행기는 온톨로지 8장 초안용 예제이며 일반 주제 자동 생성기가 아님. 새 주제에는 문안뿐 아니라 그림 종류·페이지 수·분류 라벨·그림 설명·출처도 함께 수정함. 이전 주제의 상자나 예시가 남지 않았는지 확인함. 새로 생성한 그림의 전체 문구를 글리프 검사와 문장 검사에 포함함.

그림 원고와 제작 파일 해시는 결과의 `render-report.json`에 보관함. 작업 폴더의 제작 코드도 유지함. 원본 단위를 PNG 한 장으로만 남기지 않으며, 편집용 PPTX의 글자와 도형을 같은 제작 자료에서 생성함. PPTX를 실제 앱에서 열어 확인하지 않았다면 구조 검사와 구분해서 보고함.

## 제출 전 확인

- 문장만 읽어도 업무 상황을 이해할 수 있고, 그림만 보아도 연결 대상과 관계를 알 수 있음.
- 용어·예시 이름·연결 방향·종류의 포함 관계를 본문과 대조함.
- 모든 장에서 글자 잘림·글자 간 겹침·캐릭터 겹침·대비 경고를 확인함.
- 연결선 위 글자와 상자 테두리 사이에 읽을 수 있는 간격을 둠.
- 전체 크기와 실제 표시 크기에서 확인함. 자동 좌표 검사는 시각 검수를 대신하지 않음.
- 예시가 사실처럼 표시되지 않았는지 확인하고 기존 문안 승인 절차를 유지함.

# 캐릭터로 업무 그림을 안내하는 방법

## 역할과 크기

캐릭터를 배치하기 전에 해당 장에서 할 일을 정함. 질문, 관계 설명, 종류별 사례 안내, 변경 확인 중 필요한 역할을 선택함. 남는 모서리에 넣거나 매 장의 요약 상자 옆에 반복 배치하지 않음.

1080px 논리 너비에서 주요 캐릭터 높이는 180~260px를 시작점으로 삼음. 본문과 그림의 크기를 먼저 확보하고 원본 비율을 유지함. 표지와 마지막 장의 보조 캐릭터는 더 작게 배치할 수 있음. 최소 크기를 맞추려고 그림을 가리거나 문장을 축소하지 않음.

표지와 마지막 장에는 세 종을 모두 사용함. 일렬로 세우는 방식은 의무가 아님. 중간 장은 설명할 내용에 따라 한 종 또는 여러 종을 선택함. 단순한 순환 순서보다 역할과 그림의 구성을 우선함.

## 장면 선택

| 내용 | 배치 | 확인할 점 |
|---|---|---|
| 업무 질문 | 질문 캐릭터와 짧은 말풍선을 그림 앞에 배치 | 답변은 본문이나 다음 그림에서 실제로 제시함 |
| 대상 사이의 관계 | 설명 포즈를 관계 이름 가까이에 배치 | 손동작이 모든 원본 포즈에서 정확히 대상을 가리킨다고 가정하지 않음. 위치와 말풍선으로 설명 대상을 명확히 함 |
| 종류와 사례 | 종류별 영역 안에 캐릭터와 사례 이름을 함께 배치 | 캐릭터 자체를 해당 종류의 실제 사례로 오해하지 않도록 대상 이름을 표시함 |
| 포함 관계 | 중첩 상자 옆에 결론을 말하는 캐릭터 배치 | 상자 경계·이름·포함 관계를 가리지 않음 |
| 변경 확인 | 같은 기준의 변경 전후 그림 옆에 확인 캐릭터 배치 | 바뀐 내용과 담당자가 해야 할 일을 명시함 |
| 직접 해보기 | 입력할 항목과 작성 공간 가까이에 안내 캐릭터 배치 | 쓰는 공간을 캐릭터로 채우지 않음 |

말풍선은 한두 문장으로 제한하고 제목·본문을 그대로 반복하지 않음. 꼬리의 방향으로 발화 주체를 구분함. 말풍선의 꼬리는 관계를 나타내는 화살표와 모양·위치를 구분함. 설명 문장과 캐릭터의 말은 친근한 해요체를 사용함.

카드 아래 여백에는 설명 그림, 사례 이름, 비교 결과, 연습 공간을 먼저 배치함. 캐릭터가 내용과 떨어져 있는 장식처럼 보이면 크기만 늘리지 말고 위치와 역할을 다시 정함. 요약 상자는 필요한 장에만 사용하며 왼쪽 색상 선을 모든 장에 반복하지 않음.

## 제작과 검수

`assets/ontology-character-example/`은 온톨로지 8장에 역할별 캐릭터 배치를 적용한 실행 예제임. 전체 폴더를 작업 폴더로 복사한 다음 아래와 같이 실행함.

```text
python <PROJECT>/build.py --skill-root <SKILL> --out <NEW_OUTPUT>
```

이 예제는 범용 자동 배치 엔진이 아님. 다른 주제에서는 문안·관계 그림·캐릭터 역할·그림 설명을 함께 수정함. 기본 build 명령만 실행하면 이 장면 구성이 자동 적용되는 것으로 설명하지 않음.

글리프, 글자끼리의 겹침, 글자와 캐릭터의 겹침, 색 대비를 확인함. 캐릭터 원본 해시와 결과 ZIP 무결성을 별도로 검사함. PNG 전 페이지를 큰 화면과 작은 표시 크기에서 확인하며 자동 좌표 검사를 시각 검수로 대신하지 않음. 편집형 PPTX의 구조 검사와 실제 PowerPoint 표시 확인을 구분함.

## 카드뉴스 문체

사용자 지정에 따라 제목·본문·관계 이름·말풍선·독자 안내는 해요체로 통일함. ‘있나요?’, ‘해요’, ‘정해요’, ‘적어 봐요’처럼 자연스럽게 작성함. 명사 뒤에는 받침에 맞춰 ‘이에요’와 ‘예요’를 구분함. 조건·가능성·확인 책임은 유지하며 반말이나 유아용 말투로 바꾸지 않음. 출처 원문 인용과 실제 고유명사는 보존함. 내부 제작 문서는 명사형 기준을 유지함.

이 문체는 사용자가 지정한 카드뉴스 기준이며 공통 발표자료의 합니다체 기본값보다 우선함. 제출 전 PNG·PPTX·미리보기에서 ‘합니다’, ‘봅니다’, ‘입니다’, ‘습니까’ 등의 이전 종결이 남았는지 확인함.
